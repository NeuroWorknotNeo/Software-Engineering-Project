Проект: «Оптимизатор портфеля по Марковицу: эффективная граница и бэктест с ребалансировкой».

Статус: v0.2 (19.11.2026) — решения по данным, ставке и методу оптимизации приняты. Статус реализации — в матрице трассировки, ARCHITECTURE.md.

1. Цель

Консольное приложение на C++ строит оптимальные портфели по теории Марковица на исторических ценах российских акций и проверяет, насколько эти портфели работают на новых данных (бэктест) по сравнению с простым равновзвешенным портфелем 1/N.

2. Исходные данные и допущения

Параметр Значение
Активы ~20 ликвидных акций из индекса IMOEX, торгуемых на MOEX (режим TQBR) весь период
Период 01.01.2019 – 31.12.2025
Частота дневные цены закрытия
Источник публичный API Мосбиржи (ISS), выгрузка скриптом в CSV
Доходности простые дневные; годовые величины — умножением на 252 (σ — на √252)
Безрисковая ставка постоянная на весь расчёт, параметр запуска; по умолчанию 10% годовых (около средней ключевой ставки ЦБ за 2019–2025)

Список тикеров (утверждён; в выборку вошли бумаги, торговавшиеся весь период без смены тикера): SBER, GAZP, LKOH, ROSN, NVTK, TATN, SNGS, GMKN, PLZL, CHMF, NLMK, MAGN, ALRS, PHOR, MTSS, RTKM, MGNT, MOEX, AFLT, IRAO.

Известные особенности данных:

  • торги акциями на MOEX не проводились с 28.02.2022 по 23.03.2022 — доходность через этот разрыв считается одним наблюдением;
  • у части бумаг были сплиты (например, GMKN 1:100 в 2024 году) — цены до сплита нужно пересчитать, иначе получится ложная доходность −99%;
  • цены закрытия не учитывают дивиденды — это ограничение модели (см. раздел 5).

Приоритеты (MoSCoW): M — обязательно, S — желательно, C — если хватит времени.

4. Нефункциональные требования

ID Требование Как проверяется
NFR-1 Производительность: эффективная граница из 50 точек без коротких продаж для 50 активов × 1000 дней строится (вместе с оценкой ковариации) не дольше 1 секунды в сборке Release на раннере GitHub Actions бенчмарк в CI на синтетических данных
NFR-2 Точность: решение без коротких продаж удовлетворяет условиям оптимальности (KKT) с точностью 1e-8; если ограничение w ≥ 0 неактивно, совпадает с аналитическим решением с точностью 1e-8 unit-тесты
NFR-3 Воспроизводимость: одинаковые входные данные и параметры дают одинаковый результат; пример данных лежит в репозитории, запуск без интернета тест, CI без доступа к MOEX
NFR-4 Переносимость: Linux, CMake ≥ 3.20, GCC ≥ 11 или Clang ≥ 14, C++20; запуск в Docker-контейнере CI, Dockerfile
NFR-5 Качество кода: сборка без предупреждений с -Wall -Wextra -Wpedantic; проверки clang-format и clang-tidy в CI CI
NFR-6 Тестируемость: каждое требование M и S покрыто хотя бы одним тестом (матрица трассировки в docs/ARCHITECTURE.md) ревью
NFR-7 Интерфейс: только консоль и файлы, без графического интерфейса —
NFR-8 Надёжность: некорректные входные данные (нет файла, битый CSV, вырожденная ковариация, невыполнимые ограничения) дают понятное сообщение и ненулевой код возврата, без падения unit-тесты, тесты CLI
NFR-9 Документация: API в Doxygen на GitHub Pages; итоговый отчёт в PDF (LaTeX) в репозитории CI

5. Ограничения модели (сознательно не делаем)

  • Дивиденды не учитываются: доходности считаются по ценам закрытия. Для российских акций это заметно занижает доходность — отмечается в отчёте.
  • Безрисковая ставка постоянна на весь расчёт, хотя ключевая ставка ЦБ в 2019–2025 годах менялась от 4.25% до 21%.
  • Нет внутридневных данных, проскальзывания, налогов, маржинальных требований к коротким позициям.
  • Нет графического интерфейса (требование курса).
  • Не реализуются альтернативные модели: Black–Litterman, CVaR-оптимизация, риск-паритет.
