# Требования

Проект: **«Оптимизатор портфеля по Марковицу: эффективная граница и бэктест с ребалансировкой»**.

Статус: черновик v0.1 (16.11.2026).

## 1. Цель

Консольное приложение на C++ строит оптимальные портфели по теории Марковица
на исторических ценах российских акций и проверяет, насколько эти портфели
работают на новых данных (бэктест) по сравнению с простым равновзвешенным
портфелем 1/N.

## 2. Исходные данные и допущения

| Параметр | Значение |
|---|---|
| Активы | ~20 ликвидных акций из индекса IMOEX, торгуемых на MOEX (режим TQBR) весь период |
| Период | 01.01.2019 – 31.12.2025 |
| Частота | дневные цены закрытия |
| Источник | публичный API Мосбиржи (ISS), выгрузка скриптом в CSV |
| Доходности | простые дневные; годовые величины — умножением на 252 (σ — на √252) |
| Безрисковая ставка | параметр запуска (годовая, постоянная на весь расчёт) |

Предварительный список тикеров (уточняется на этапе загрузки данных):
SBER, GAZP, LKOH, ROSN, NVTK, TATN, SNGS, GMKN, PLZL, CHMF, NLMK, MAGN,
ALRS, PHOR, MTSS, RTKM, MGNT, MOEX, AFLT, IRAO.

**Известные особенности данных:**
- торги акциями на MOEX не проводились с 28.02.2022 по 23.03.2022 — доходность
  через этот разрыв считается одним наблюдением;
- у части бумаг были сплиты (например, GMKN 1:100 в 2024 году) — цены
  до сплита нужно пересчитать, иначе получится ложная доходность −99%;
- цены закрытия не учитывают дивиденды — это ограничение модели
  (см. раздел 5).

## 3. Функциональные требования

Приоритеты (MoSCoW): **M** — обязательно, **S** — желательно, **C** — если хватит времени.

### Данные

| ID | Требование | Приоритет |
|---|---|---|
| FR-1 | Скрипт на Python выгружает дневные цены закрытия выбранных тикеров с MOEX ISS в CSV формата `date,TICKER1,TICKER2,...` | M |
| FR-2 | Приложение читает CSV с ценами, проверяет формат и сообщает о некорректных строках | M |
| FR-3 | Даты выравниваются по общему торговому календарю; пропуски внутри ряда заполняются последней известной ценой, пропуски в начале ряда — ошибка | M |
| FR-4 | Цены корректируются на сплиты по списку из конфигурационного файла `splits.csv` | M |
| FR-5 | Аномальные дневные доходности (по модулю больше заданного порога, по умолчанию 50%) выводятся как предупреждение с датой и тикером | S |

### Статистика

| ID | Требование | Приоритет |
|---|---|---|
| FR-6 | Расчёт вектора средних доходностей μ и выборочной ковариационной матрицы Σ | M |
| FR-7 | Оценка ковариации со сжатием Ledoit–Wolf (к масштабированной единичной матрице) с выводом коэффициента сжатия | S |
| FR-8 | Выбор метода оценки ковариации параметром запуска | S |

### Оптимизация с разрешёнными короткими продажами (аналитически)

| ID | Требование | Приоритет |
|---|---|---|
| FR-9 | Портфель минимальной дисперсии (GMV) | M |
| FR-10 | Портфель максимального коэффициента Шарпа (касательный) при заданной безрисковой ставке | M |
| FR-11 | Эффективная граница из N точек (N — параметр, по умолчанию 50) | M |

### Оптимизация без коротких продаж (веса ≥ 0)

| ID | Требование | Приоритет |
|---|---|---|
| FR-12 | Портфель минимальной дисперсии с ограничением w ≥ 0 | M |
| FR-13 | Портфель максимального Шарпа с ограничением w ≥ 0 | M |
| FR-14 | Эффективная граница из N точек с ограничением w ≥ 0 | M |
| FR-15 | Ограничение сверху на вес одного актива (например, не больше 20%) | C |

### Бэктест

| ID | Требование | Приоритет |
|---|---|---|
| FR-16 | Бэктест со скользящим окном оценки (по умолчанию 252 дня) и ежемесячной ребалансировкой; на дату ребалансировки используются только данные до этой даты | S |
| FR-17 | Стратегии в бэктесте: GMV, максимальный Шарп (обе — с короткими продажами и без), равновзвешенный портфель 1/N | S |
| FR-18 | Метрики стратегий: годовая доходность, годовая волатильность, коэффициент Шарпа, максимальная просадка, средний оборот портфеля | S |
| FR-19 | Пропорциональные транзакционные издержки при ребалансировке (параметр, по умолчанию 0) | C |

### Интерфейс и вывод

| ID | Требование | Приоритет |
|---|---|---|
| FR-20 | Консольный интерфейс с командами `stats`, `optimize`, `frontier`, `backtest` и параметрами в виде флагов; `--help` выводит справку | M |
| FR-21 | Краткая сводка выводится в stdout, подробные результаты (веса, точки границы, кривая капитала) — в CSV-файлы | M |

## 4. Нефункциональные требования

| ID | Требование | Как проверяется |
|---|---|---|
| NFR-1 | **Производительность:** эффективная граница из 50 точек без коротких продаж для 50 активов × 1000 дней строится (вместе с оценкой ковариации) не дольше 1 секунды в сборке Release на раннере GitHub Actions | бенчмарк в CI на синтетических данных |
| NFR-2 | **Точность:** решение без коротких продаж удовлетворяет условиям оптимальности (KKT) с точностью 1e-8; если ограничение w ≥ 0 неактивно, совпадает с аналитическим решением с точностью 1e-8 | unit-тесты |
| NFR-3 | **Воспроизводимость:** одинаковые входные данные и параметры дают одинаковый результат; пример данных лежит в репозитории, запуск без интернета | тест, CI без доступа к MOEX |
| NFR-4 | **Переносимость:** Linux, CMake ≥ 3.20, GCC ≥ 11 или Clang ≥ 14, C++20; запуск в Docker-контейнере | CI, Dockerfile |
| NFR-5 | **Качество кода:** сборка без предупреждений с `-Wall -Wextra -Wpedantic`; проверки clang-format и clang-tidy в CI | CI |
| NFR-6 | **Тестируемость:** каждое требование M и S покрыто хотя бы одним тестом (матрица трассировки в `docs/ARCHITECTURE.md`) | ревью |
| NFR-7 | **Интерфейс:** только консоль и файлы, без графического интерфейса | — |
| NFR-8 | **Надёжность:** некорректные входные данные (нет файла, битый CSV, вырожденная ковариация, невыполнимые ограничения) дают понятное сообщение и ненулевой код возврата, без падения | unit-тесты, тесты CLI |
| NFR-9 | **Документация:** API в Doxygen на GitHub Pages; итоговый отчёт в PDF (LaTeX) в репозитории | CI |

## 5. Ограничения модели (сознательно не делаем)

- Дивиденды не учитываются: доходности считаются по ценам закрытия.
  Для российских акций это заметно занижает доходность — отмечается в отчёте.
- Безрисковая ставка постоянна на весь расчёт, хотя ключевая ставка ЦБ
  в 2019–2025 годах менялась от 4.25% до 21%.
- Нет внутридневных данных, проскальзывания, налогов, маржинальных требований
  к коротким позициям.
- Нет графического интерфейса (требование курса).
- Не реализуются альтернативные модели: Black–Litterman, CVaR-оптимизация,
  риск-паритет.
